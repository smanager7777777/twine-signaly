## 1. Что это
**«Twine СИГНАЛЫ»** — обычный Twine 2.12.1 (русский интерфейс уже есть), в который добавлены формы и предпросмотр для терминала. Карта экранов, «Играть», «Тест», «Опубликовать», импорт и экспорт остаются как в Twine.

**Главное правило:** всё, что делает «Twine СИГНАЛЫ», сохраняется внутри самой истории обычными средствами Twine — пассажами, «JavaScript истории» и «Таблицей стилей». Поэтому история открывается и работает **в обычном Twine без надстройки** (решение 24). Без надстройки просто не будет удобных форм. Исключение — **файлы в папке игры, которые делает программа:** развёрнутые копии для реверса (`media/audio/reverse/`) и картинки SSTV (`media/img/sstv/`); их нужно переносить вместе с игрой.

## 3. Как хранятся настройки и блоки
- **Служебные блоки** — в «JavaScript истории», «Таблице стилей» и StoryInit, между метками «СИГНАЛЫ: …». Код автора вне меток не трогается (кроме узнаваемых кусков шаблона, которые заменяются: старый блок «общие настройки», код KR2, код звуков наведения и нажатия, код таймера Clocks; простые `<<set>>` StoryInit, которые окно «Переменные» переносит в свой раздел; окна `<<script>>Dialog.create…<</script>>` внутри ссылок → `<<sg-open>>`; код «Горячие клавиши мастера» (Shift+Z+A/B/C) → пассаж «Горячие клавиши», только если весь код совпадает с шаблоном). Метки и замена блока — `src/util/signaly/signaly-blocks.ts`.
- **Движок терминала** — блок «СИГНАЛЫ: движок терминала» в JavaScript истории, с номером версии (сейчас **27**). Одинаков для всех историй; настройки читает из CSS-переменных `--sg-…`, наборы звуков — из `setup.signalySounds`, горячие клавиши — из пассажей с тегом `sg-keys`, общую таблицу кодов — из `sg-codes`, события — из `sg-event`, строку событий и цикл — из `sg-ticker`, доступ к экранам — из `sg-access`, общий пассаж блокировки — по тегу `sg-lock`, статьи — из `sg-article`, музыку — из `sg-music`, виды радио — из `sg-radio`, **картинки SSTV — из `sg-sstv`**, способы первого посещения — из переменных `--sg-first-<id>` блока оформления, экран — по тегу `sg-first-<id>`. Новая версия ставится, когда автор нажимает «Сохранить» в окнах программы, вставляет первый блок или эффект или пишет в форме команду движка (`<<sg-…>>`); заодно (`src/dialogs/signaly-upgrade.ts`, `saveStoryWithUpgrade`) переносится узнанный код шаблона (кнопки на экране, звуки, таймеры, окна PRCDTEST, горячие клавиши, камеры, подсказки, музыка). Условия, состояния, значения и большинство действий движку не нужны — это обычные команды SugarCube; заходы на экраны и коды сотрудников в условиях — функции движка `setup.visits()`, `setup.entered()`.
- **Общие настройки** — блок «СИГНАЛЫ: оформление терминала» в таблице стилей: строка-комментарий `СИГНАЛЫ-настройки: {…}` и обычный CSS. Там же окна-сообщения `#ui-dialog…`, настройки печати, правила глитча.
- **Виды кнопок и ссылок** — блок «СИГНАЛЫ: виды кнопок и ссылок» сразу после блока оформления. В пассаже — `<span class="amber">…</span>`. Ссылка или кнопка того же вида (`signaly-link-form.ts`) — меняется только `<<link>>` ↔ `<<button>>` (и `[[…]]`), обёртка вида остаётся.
- **Звуки наведения и нажатия** — блок «СИГНАЛЫ: звуки наведения и нажатия» в JavaScript истории (`setup.signalySounds`). Разбор и запись — `signaly-sounds.ts`.
- **Звуковые файлы, группы, плейлисты** — обычные `<<cacheaudio>>`, `<<createaudiogroup>>`, `<<createplaylist>>` в StoryInit, раздел между метками окна «Звуки».
- **Переменные** (`signaly-variables.ts`) — обычные `<<set $имя to значение>> /* Подпись */` в StoryInit, раздел между метками окна «Переменные». Список переменных для форм (`knownVariables`) — раздел окна и все `$имя` в тексте экранов (служебные `$sg…` — нет).
- **Блоки экрана** — короткие команды движка в тексте пассажа: `<<sg-image>>`, `<<sg-video>>`, `<<sg-alarm>>…<</sg-alarm>>`, `<<sg-dialog>>…<</sg-dialog>>`, `<<sg-code>>` с `<<sg-case>>`/`<<sg-wrong>>` (слово `table` — проверять ещё и по общей таблице кодов), `<<sg-place>>…<</sg-place>>`, окно KR2, `<<sg-timer>>`, `<<sg-chain>>` с `<<sg-step>>`. Разбор и запись — `signaly-screen-blocks.ts`; непонятые слова сохраняются.
- **Условие, состояния, значение** (`signaly-logic.ts`) — `<<if …>>…<<else>>…<</if>>` (включена / выключена / равна / не равна / больше / меньше; был / не был на экране, заходил не меньше / ровно N раз: `setup.visits("Экран") gt 0 | is 0 | gte N | is N`; сотрудник ввёл / не ввёл код: `setup.entered("2", "101")`), `<<switch $x>><<case 0>>…\ … <</switch>>`, `<span class="sg-value">Подпись: <<= $x>></span>` (или `<<= setup.visits("Экран")>>`). Формы — `signaly-logic-form.tsx` (строки условий — общий `CondRows` с «Что проверять»; списки экранов, сотрудников и кодов — `CondListsContext`).
- **Действия** (шаги 3.2–3.5, `signaly-actions.ts`) — команды внутри `<<link "Надпись" "Экран">>…<</link>>` / `<<button>>` (или `[[Надпись|Экран][$x to 1]]`), внутри `<<sg-key>>` и `<<sg-entry>>`, по порядку, затем переход: `<<set>>`, `<<audio>>`/`<<playlist>>`, `<<sg-sound>>` (звук-сигнал, приглушение `duck`), `<<sg-open>>` (окно), `<<sg-timer … hidden>>` (запуск таймера), `<<sg-timer-stop>>`, `<<if>>…<<else>>…<</if>>` и `<<timed Ns>>…<</timed>>` со своими списками внутри, `<<sg-progress N>>` — «прогресс вводящего +N» (только в таблице кодов), `<<sg-back>>` — «вернуться на экран, где были», `<<sg-mus …>>` — «Музыка»; прочее — строкой «Код». Нетронутое записывается дословно. Список действий — общий компонент `signaly-action-list.tsx`.
- **Горячие клавиши** (шаг 3.3, `signaly-keys.ts`) — пассаж «Горячие клавиши» с тегом `sg-keys`: `<<sg-key "Shift+Z+A" "Подпись" [goto "Экран"] [ask]>>действия<</sg-key>>`; встроенные — `builtin newgame` / `builtin alarm` (комбинацию можно поменять, удалить нельзя). Окно — `src/dialogs/signaly-keys/`.
- **Общая таблица кодов** (шаг 3.4, `signaly-codes.ts`) — пассаж «Коды» с тегом `sg-codes`: `<<sg-replies …>>`, `<<sg-person "3" pin "417" var "$progress3">>`, `<<sg-entry "205" "Подпись" [who …] [once all|each] [title …] [goto …] [denied …] [used …]>>действия<<sg-answer>>ответ<</sg-entry>>`. Отметки одноразовых кодов — `$sgUsed`; коды, введённые каждым сотрудником, — `$sgEntered`. Окно — `src/dialogs/signaly-codes/`.
- **События** (шаг 3.5, `signaly-events.ts`) — обычный пассаж с тегом `sg-event`, первой строкой `<<sg-event [repeat] [delay N] [priority N] условие>>`. Форма — `signaly-event-form.tsx` (кнопка «Событие» на панели над текстом). Отметки — `$sgEvents`, откуда перешли — `$sgEventFrom`, заходы на экраны — `$sgVisits`.
- **Виды экранов, стили текста, поля ввода** (шаг 4.2, `signaly-screens.ts`) — поля `screens`, `textStyles`, `input…` в настройках блока оформления и обычный CSS в нём же. Вид экрана — тег пассажа `sg-scr-<id>`, правила `html[data-tags~="…"]` (SugarCube сам ставит теги на `<html>`), поэтому движок не нужен. Стиль текста — `<span class="sg-ts-<id>">`. Места «на экране» считаются от `--sg-win-…`, вид их не меняет.
- **Закрытые экраны** (шаг 4.3, `signaly-access.ts`) — экран с тегом `sg-access`, первой строкой `<<sg-access [lock "Экран"] [links …] [codes …] [keys …] [events …] [auto …]>>условие<<sg-rule вид "id" [from "Экран"] do поведение [to "Экран"]>><</sg-access>>\`. Форма — `signaly-access-form.tsx`, список источников — `accessSources`. Общий пассаж блокировки — тег `sg-lock`.
- **Статьи** (шаг 4.4, `signaly-articles.ts`) — экран с тегом `sg-article`, первой строкой `<<sg-article [title …] [section …] [order N] [back …]>>\`. Форма — `signaly-article-form.tsx`. Список — блок `<<sg-articles [sections "А, Б"] [form button] [kind …] [columns N] [headings]>>`, собирается движком при показе экрана. Откуда открыли статью — `$sgArticles`. Общая надпись «Назад», её вид и «кнопкой» — поля `articleBack`, `articleBackKind`, `articleBackButton` блока оформления, переменные `--sg-article-…`.
- **Первое посещение** (шаг 4.5, `signaly-first.ts`) — поле `firstWays` настроек блока оформления, переменные `--sg-first-<id>`; на экране — тег `sg-first-<id>`, как у вида экрана. Вкладка — `signaly-first-tab.tsx`, кнопка над текстом — в панели, проиграть — `setup.signaly.firstDemo`.
- **Список состояний** (шаг 5.1, `signaly-screen-blocks.ts`) — блок `<<sg-list [form …] [columns N]>>` с `<<sg-state значение label … [kind …] [color …] [keykind …] [do row|window] [goto …] [title …]>>действия` и `<<sg-row "номер" "название" var "$x" passage "Экран" [key]>>`. Форма — `signaly-list-form.tsx`. Состояние строки — значение её переменной, блок своего состояния не хранит. Процедуры и ИНЖИНАРИУМ — этот блок кнопками и плиткой.
- **Терминал взлома** (шаг 5.2, `signaly-screen-blocks.ts`, `signaly-hack.ts`) — блок `<<sg-hack слова>>` с частями `<<sg-hack-win>>`, `<<sg-hack-fail>>`, `<<sg-hack-miss>>` (действия как у ссылки). Форма — `signaly-hack-form.tsx`. Значения по умолчанию — `hackDefaults`, общие для формы и движка. Состояние — `$sgHack`. Экран «Хактест» шаблона переносится в блок, только если весь код совпал (контрольное число).
- **Камера** (шаг 5.3, `signaly-screen-blocks.ts`, `signaly-camera.ts`) — блок `<<sg-camera [source "window"] width … height … [vwidth … vheight … shiftx … shifty …] [button …] [nosignal …] [nocolor …] [nonoise N] [место, рамка]>>`. Форма — `case 'camera'` в `signaly-block-panel.tsx`. Значения по умолчанию — `cameraDefaults`, общие для формы и движка. Подключение хранит движок, в историю ничего не пишется. Экраны шаблона переносятся, только если код узнан целиком; код истории убирается, только если им больше никто не пользуется.
- **Подсказка при наведении** (шаг 5.4, `signaly-tip.ts`) — команда шаблона `<<hovertip "Текст" [ширина]>>текст<</hovertip>>`, её понимает движок. Форма — `signaly-tip-form.tsx`. Вид — поля `tip…` настроек, переменные `--sg-tip-…` в блоке оформления, правила `tipBase` в стиле движка. Код шаблона убирается, только если совпало контрольное число; изменённый код остаётся, движок команду тогда не объявляет.
- **Картинка-переключатель** (шаг 5.4) — слова `second`, `toggle`, `sound`, `volume` блока `<<sg-image>>`. Значение — сама переменная, блок ничего не хранит.
- **Звук первого посещения** (шаг 5.4) — поля `sound`, `volume` способа, два последних слова значения `--sg-first-<id>`; без звука значение прежнее.
- **Живое значение** (этап 6) — текст блока прежний, движок оборачивает команду `<<=>>` внутри `.sg-value`: `span.sg-value-now` хранит выражение в атрибуте и 4 раза в секунду сверяет значение.
- **Запомнить открытое** (этап 6, `signaly-effects.ts`) — `<<sg-reveal "sg-revealN" "Надпись" [link] [kind "вид"]>>текст<</sg-reveal>>` вместо обычного раскрытия; отметки — `$sgRevealed`.
- **Музыка** (шаг 7.1, `signaly-music.ts`) — пассаж «Музыка» с тегом `sg-music`: `<<sg-music volume 30 spin 0.8 [auto]>>`, `<<sg-folder "Папка" section ambient|radio|air|jam>>`, `<<sg-track "Название" "файл" [pre "файл" wait N tail N prevolume N] [start N]>>условие<</sg-track>>`. Окно — `src/dialogs/signaly-music/`. Действие ссылок, кнопок, клавиш, кодов — `<<sg-mus …>>` (`MusicAction` в `signaly-actions.ts`). Блок «Громкость» — `<<sg-volume>>`. Музыка экрана — первая строка `<<sg-screen-music …>>\`, форма `signaly-screen-music-form.tsx`. Состояние игры — `$sgMusic`. Плеер — свой `Audio` мимо SimpleAudio.
- **Радио** (шаг 7.2, `signaly-radio.ts`) — пассаж «Радио» с тегом `sg-radio`: `<<sg-radio-view "Имя" type broken|fixed|reverse|decoder frame "#…" elements "#…" label "…" sparks N [sparksound "…" sparkvolume N]>>`; порядок строк — порядок радио в игре (сессия 30). Окно — `src/dialogs/signaly-radio/`. Блок экрана — `<<sg-radio "Имя" [size N]>>`: движок рисует каркас (SVG в квадрате 1000×1000) и элементы поверх; радио — пульт общего плеера «Музыки». Откуда пришли на радио — `$sgMusic.from`.
- **Вложенные папки, громкость файла, эфир** (шаг 7.3, `signaly-music.ts`, `signaly-radio.ts`) — вложенная папка — путь через «/» в имени `<<sg-folder>>`, раздел как у верхней; `gain N` у трека; раздел `air` — передачи с `to "Папка радио"`, `width`, `text`; эфир вида — `noise`, `noisevolume`, `noiseranges`, `jamsmin`, `jamsmax`, `incoming`, `catch` у `<<sg-radio-view … type fixed>>`. Частота, поиск, пойманное — `$sgMusic.freq`, `scan`, `caught`. Пойманная передача — трек своей папки радио в каталоге.
- **Помехи** (сессия 30, `signaly-music.ts`) — раздел `jam` пассажа «Музыка»: `<<sg-folder "Вид радио" section jam>>` и обычные треки с `width N`; папки — по видам с эфиром (`syncJamFolders`), старая запись `jam "файл|ширина|громкость; …"` у вида переносится в «Музыку» при её открытии и убирается после «Сохранить» (`withoutLegacyJams`), а пока не перенесена — движок читает её сам. Переименование вида в окне «Радио» переименовывает папку (`renameJamFolder`). Пойманная помеха — трек папки радио «Помехи» (своя `section radio` с этим именем или виртуальная).
- **Цвета частей радио, реверс, декодер** (сессии 29, 30, `signaly-radio.ts`, `signaly-reverse.ts`) — слова `buttons`, `power`, `scale`, `lamp`, `catalog`, `decoder`, `inner` у `<<sg-radio-view>>` (нет — как у элементов, лампочка — как у шкалы, внутренний — как у каркаса); `type reverse` — каркас В2 с эфиром, РЕВЕРС и катушками; `type decoder` — каркас Д2: то же плюс ДЕКОД и окно картинки. Свой файл задом наперёд — `reverse "файл"` у `<<sg-track>>`; иначе копия программы `media/audio/reverse/<путь>.wav` (моно 22 050 Гц, сессия 30) — это файл в папке игры, в историю ничего не пишется. Копии делаются при «Сохранить» в окнах «Музыка» и «Радио» и кнопкой «Сделать копии» окна «Проверка истории» (`src/dialogs/signaly-reverse-copies.ts`): Chromium программы раскладывает звук на отсчёты, они пишутся в WAV задом наперёд.
- **Картинки SSTV** (сессия 30, `signaly-sstv.ts`, `signaly-sstv-store.ts`, `src/dialogs/signaly-sstv-images.ts`) — игра из папки звук своих файлов прочитать не может (Chrome отдаёт тишину, CORS), поэтому разбирает программа: при «Сохранить» в окне «Музыка», если есть радио с декодером, помехи и передачи, изменившиеся с прошлого раза (отметка «время-размер»), раскладываются на отсчёты (22 050 Гц, моно), `decodeSstv` находит заголовок VIS, режим и строки по синхроимпульсам (с поправкой на часы передатчика), картинка пишется PNG в `media/img/sstv/`, а где она в звуке — строкой `<<sg-sstv "трек" stamp … img … mode … at … line … rows … per … width … height …>>` в пассаже «SSTV» (тег `sg-sstv`). Движок набирает готовую картинку строка за строкой в такт звуку.
- **«Каталог Атмосферы»** (шаг 7.2) — блок `<<sg-ambient [columns N] [kind …] [buttons]>>`; альбомы — папки раздела «Атмосфера», подсказка — `tip` у `<<sg-folder>>`; прослушанные треки — `$sgMusic.done`, «Случайно» — `$sgMusic.shuffle` (у радио — своё `rshuffle`, сессия 30).
- **Перевод музыки шаблона** (шаг 7.2, `signaly-music-template.ts`) — `moveTemplateMusic` при установке движка: StoryInit, Start, audiobuttons, radio, «Атмосфера» → каталог, действие «Музыка», блоки; только если узнан весь код.
- **Перебор картинками** (сессия 26) — `form image`, `width`, `sound`, `volume` у `<<sg-pick>>`, `img` у `<<sg-opt>>`.
- **Старое «Окно-сообщение»** (сессия 26) — `<<sg-dialog>>` остаётся рабочим блоком движка, но в программе это ссылка с действием «Открыть окно» (`findLinks`); в «Добавить блок» его нет.
- **Вставить экран** (сессия 25) — обычный `<<include "Экран">>`, блок `include` в `signaly-screen-blocks.ts`; движок не нужен.
- **Проверка истории** (сессия 25, `signaly-check.ts`) — ничего не пишет в историю: читает пассажи, «JavaScript истории», таблицу стилей и список файлов папки игры; с сессии 30 — ещё треки без развёрнутой копии (через главный процесс) и кнопка «Сделать копии».
- **Живые статусы KR2** (сессия 25) — текст прежний; движок перевыводит зону статусов 4 раза в секунду и заменяет её только при отличии.
- **Русские надписи** (`signaly-l10n.ts`) — движок дописывает их в `l10nStrings`; код автора стоит ниже и потому главнее.
- **Дешифратор** (шаг 4.5) — обычный экран с блоком «Поле кода» и словами `table digits`; пароли — строки таблицы кодов, метка `decoder` только для окна; условие кода — `<<sg-when>>` и `lock` у `<<sg-entry>>`.
- **Переименование экрана** (`signaly-rename.ts`) — `update-passage.ts` после правки `[[…]]` прогоняет все пассажи через `renameScreen`.
- **Строка событий и цикл** (шаг 4.1, `signaly-ticker.ts`) — пассаж «Строка событий» с тегом `sg-ticker`: `<<sg-ticker screen "Start" height 48 size 22 font "…" speed 60 pause 2 hold 8 change 1.5 mode fade|scroll order "new,general,seen">>`, `<<sg-cycle var "$progress" spin 10 gap 0.5 from "20,20,20,20,20" to "2,2,2,2,2" sound "…" volume 100>>`, `<<sg-cycle-at 7 "00487">>`, `<<sg-news "Имя" [general] [priority N] [minutes N] [times N] [color "#…"] [bold] [italic] [effect blink|glitch]>>условие<<sg-text>>текст<</sg-news>>`. Состояние игры — `$sgTicker`. Окно — `src/dialogs/signaly-ticker/`.
- **Таймеры** (шаг 2.3) — время окончания в переменной `$sgTimers` (`{имя: {end, goto, title, text, passage, sound}}`), поэтому таймер идёт в фоне и попадает в автокопию; табло — `.sg-timer[data-sg-timer]`.
- **Эффекты текста** — обычные команды SugarCube и HTML: `<<type>>`, `<<timed>>`/`<<next>>`, смена — `<span id>` + `<<timed>><<replace>>`, `<span class="sg-blink">`, `<span class="glitchy" data-text>`; `after`, `data-sg-start`, `data-sg-after`. Разбор и запись — `signaly-effects.ts`; форма — `signaly-effect-form.tsx`.
- **Статусы KR2 с условием** — `<<if $имя>>строка<br><</if>>\`.
- Синтаксис — в `03_STATUS.md`, «Как устроено хранение». Всё, что формы не понимают, остаётся текстом пассажа как есть.

## 4. Папка игры и медиа
```
СИГНАЛЫ/                 папка игры (выбирается в подробностях истории)
  27_03_2025.html        готовая игра — «Опубликовать в папку игры»
  _играть.html _тест.html  «Играть» и «Тестировать»
  media/img  media/audio  media/video  media/fonts
  media/audio/reverse    развёрнутые копии для реверса (делает программа)
  media/img/sstv         картинки SSTV для декодера (делает программа)
```
- «Играть»/«Тест» пишут игру **в папку игры**, поэтому пути `media/…` работают одинаково при проверке и в готовой игре. Игра открывается в **Chrome** (решение 19).
- Путь к папке хранится в настройках программы (`prefs.gameFolders`), ключ — IFID истории (решение 65).
- Окна программы видят файлы папки игры: шрифты, звуки, картинки, видео; предпросмотр показывает настоящие картинки; окно «Звуки» даёт прослушать файлы и наборы; форма таймера предлагает шрифты из `media/fonts`, формы — звуки из окна «Звуки» и файлы из `media/audio`. Папки `media/audio/reverse` и `media/img/sstv` в списках не показываются.
- Главный процесс (`signaly-game-folder.ts`) пишет только в свои папки: `.wav` в `media/audio/reverse/`, `.png` в `media/img/sstv/`; читает только внутри `media/`.

## 6. Движок в игре (версия 27)
- **Сессия 30:** у всех радио — полоса прогресса (`progBuild`) и «СЛУЧАЙНО» (`$sgMusic.rshuffle`, отдельно от «Случайно» Атмосферы); помехи — треки раздела «Помехи» (`musJams`, `id` «jam:Вид/Трек»), на шкалу при входе выпадают по `airJamPool` (одна пойманная этого радио, не пойманные этого и радио выше, не хватает — ещё пойманные этого), ловятся, как передачи, в папку радио «Помехи»; лампочка горит и на помехах; свой цвет лампочки (`--sg-rl`); «◀◀ РЕВЕРС НЕДОСТУПЕН», если копии нет (`mus.rev.err`); приглушение звуком-сигналом действует и на общий плеер и эфир (`mus.duck`). **Радио Д2** (`radioFrameDecoder`, `radioPlaces.decoder`): ДЕКОД (`$sgMusic.dec`, после сбоя выключен) и окно картинки; `decLoop` покадрово берёт источник (`decSource`: трек каталога или самая громкая точка эфира с картинкой; звучит не SSTV — строки помех), видимые строки — по месту трека, шум — по неточности настройки; буфер живёт до перезагрузки страницы; щелчок по окну — на весь терминал (`decToggleFull`). Картинки — `sstvTable()` из пассажей с тегом `sg-sstv`, PNG грузятся при показе радио.
- **Сессия 29:** лампочка на шкале; поимка «на 10 тише, но не тише половины», каталог прокручивается к пойманному; свои цвета частей радио. **Шаг 7.4:** радио В2 — РЕВЕРС (держать: развёрнутый файл с места «длина − где трек», место едет назад; отпустили — вперёд без предзвука), полоса прогресса, катушки, эфир как у Р2.

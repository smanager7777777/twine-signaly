- **Горячие клавиши (сессия 11)** — пассаж **«Горячие клавиши»** с тегом **`sg-keys`** (движок читает все пассажи с этим тегом при первом нажатии):
  - пояснение-комментарий, затем строки `<<sg-key "Shift+Z+A" "Подпись" [goto "Экран"] [ask]>>действия<</sg-key>>` — действия те же, что внутри ссылки, по одному на строке;

  - в поле ввода комбинация тоже срабатывает: поле возвращается к виду до нажатия Z (вместе с переменной поля — событие `input`), буква не печатается;
  - `ask` — окно «Выполнить «Подпись»?» с кнопками «Да» (`.sg-key-yes`) и «Нет» (`.sg-key-no`);
  - выполнение — `Wikifier.wikifyEval(действия)`, затем `Engine.play(goto)` или запись автокопии (`afterAction`).
- **Общая таблица кодов (сессия 12)** — пассаж **«Коды»** с тегом **`sg-codes`** (движок читает все пассажи с этим тегом при первом вводе кода):
  - пояснение-комментарий; `<<sg-replies title "Ошибка" wrong "Неверный код" denied "Нет доступа" badpin "Неверный личный код" used "Пусто" ask "Введите личный код">>` — общие тексты (заголовок окон ошибок, четыре ответа, подсказка второго поля);
  - сотрудники — `<<sg-person "3" pin "417" var "$progress3">>` (номер или имя без запятых, личный код, переменная прогресса; `var` можно не писать);
  - коды — `<<sg-entry "205" "Подпись" [who "3, Иванов"] [once all|each] [title "Заголовок ответа"] [goto "Экран"] [denied "свой «нет доступа»"] [used "свой «уже использован»"]>>действия<<sg-answer>>текст ответа<</sg-entry>>`; действия — те же, что у ссылки, плюс **`<<sg-progress N>>`** («прогресс вводящего +N»); в тексте ответа `<<= _who>>` — номер или имя того, кто ввёл, `<<= _code>>` — введённый код;
  - поле кода — `<<sg-code … table>>` (слово `table`): свои `<<sg-case>>` поля → таблица (код без пробелов по краям) → своё `<<sg-wrong>>` поля или общее «Неверный код»;
  - личный код нужен, если у кода есть `who`, `once each`, `<<sg-progress`, `_who` **или код упомянут в условии `setup.entered(…, "код")` на любом экране (сессия 13)**; тогда под полем (в `span.sg-code-pin`) — подсказка и второе поле `input.sg-code` (звёздочки, если у поля `password`; та же кнопка и отступ, что у поля); Enter или кнопка → проверка: нет такого личного кода → «Неверный личный код»; сотрудника нет в `who` → «Нет доступа»; уже использован → «Пусто»; иначе — действия, ответ окном-сообщением, переход. Одноразовый `once all`, уже использованный, отвечает «Пусто» сразу;
  - отметки — `$sgUsed`: `{"300": true, "200|3": true}`; прогресс — переменная сотрудника (пустая считается 0); **коды, введённые сотрудником, — `$sgEntered`: `{"2": ["101", "103"]}` (записывается до действий кода)**. Автокопия хранит их как остальные переменные; «Новая игра» перезапускает SugarCube — всё сначала.
- **События (сессия 13)** — обычные пассажи с тегом **`sg-event`**; движок читает их при первой проверке:
  - первой строкой — `<<sg-event [repeat] [delay N] [priority N] условие>>` (слова — до условия; условие — как в `<<if>>`); на самом экране строка ничего не выводит;
  - без `repeat` — один раз за игру; с `repeat` — каждый раз, когда условие было ложным и стало верным; `delay N` — через N секунд после того, как условие стало верным (время окончания — в `$sgEvents`, переживает смену экрана и сбой; условие снова ложно — отсчёт отменяется); `priority N` — больше число — раньше (при равной — по имени экрана);
  - проверка — 4 раза в секунду (`setInterval`), после `:passageend` и через 60 мс после щелчка, `change`, `keyup`; только после стартового клика, не во время показа экрана и не при восстановлении; в предпросмотре программы — нет;
  - готовое событие: если игроки на экране с тегом `sg-event` — ждёт, пока уйдут; если на экране этого же события — считается случившимся; **открыто окно-сообщение — ждёт, пока его закроют (ответ 2А, сессия 14)**; иначе — `$sgEventFrom` = текущий экран, `Engine.play(событие)`;
  - `$sgEvents` = `{"Экран": {done: 1} | {ready: 1} | {due: время} | {was: 1}}`;
  - **заходы на экраны** — `$sgVisits` = `{"Экран": N}`: +1 на `:passagestart`, кроме повторного показа после сбоя; в тексте и условиях — `setup.visits("Экран")` (0, если не был);
  - **«сотрудник ввёл код»** — `setup.entered("2", "101")` (по `$sgEntered`);
  - **«Вернуться на экран, где были»** — `<<sg-back>>`: на `$sgEventFrom`, если пусто — на предыдущий экран; переход — через `Engine.DOM_DELAY` (после остальных действий ссылки).
- **Виды экранов и стили текста (сессия 15)** — в строке `СИГНАЛЫ-настройки` блока оформления, поля `screens` и `textStyles`; CSS — там же, в конце блока:

Работает без движка, в обычном Twine тоже;

  - шрифт-файл вида — `@font-face` `sg-scr-font-<id>`;
  - стиль текста — `<span class="sg-ts-<id>">`, правило `.sg-ts-<id>`, шрифт-файл — `sg-ts-font-<id>`; с межстрочным интервалом — `display: inline-block`.

  - переход — `accessGo(экран, 'auto', 'hack:' + экран взлома)`, правило «Доступа» — `<<sg-rule auto "hack:Экран" do …>>`; `renameScreen` меняет `win`, `fail` и `hack:Экран`.
- **Список состояний (сессия 19)** — блок в тексте экрана, команды по строкам:
  - `<<sg-list [form button|tile] [columns N]>>` (нет `form` — ссылками), затем состояния, затем строки, затем `<</sg-list>>`;
  - состояние — `<<sg-state значение label "Надпись" [kind вид] [color "#цвет"] [keykind "вид"] [do row|window] [goto "Экран"] [title "Заголовок окна"]>>действия`: значение — число или строка, `do row` — экран строки, `do window` — он же в окне (`<<sg-open>>`), `goto` — свой экран; действия — те же, что внутри ссылки, в конце той же строки; в надписи, заголовке и действиях `{номер}`, `{название}` подставляются из строки;
  - строка — `<<sg-row "001" "Название" var "$prcd1" passage "Экран" [key]>>`; номер — строка, нули сохраняются;
  - движок: `sg-list` собирает `list` и на каждую строку — `div.sg-list-item` с полем `sgList` (`list`, `row`, `index`, `state`) в `div.sg-list-grid` (плитка — ещё `.sg-list-tiles`), `listDraw(item)` рисует обычные `<<button>>` / `<<link>>` с обёрткой вида; `listTick` (250 мс, только если список был показан) перерисовывает строку со сменившимся состоянием. Состояние не хранится: значение переменной, `State.getVar`. Цвет — класс `sg-list-color` и `--sg-state` на самом элементе;
  - плитка: `.sg-tile` (ссылка или `div`, если нет ни перехода, ни действий), внутри `.sg-tile-name`, `.sg-tile-status`;
  - `data-sg-label` — имя для «Доступа»: название строки, у состояния с `goto` — надпись без подстановки; `accessLinkId` берёт его раньше текста; `accessHide` прячет `.sg-list-item`;
  - первое посещение разбирает `.sg-list-grid` до строк.
- **Блоки экрана** — команды в тексте пассажа:
  - `<<sg-image "media/img/x.jpg" width 400 place screen corner tr x 10 y 20 border 2 color "#00cc00" glow 5>>`;
  - `<<sg-video "media/video/x.mp4" width 1000 height 1000 controls autoplay loop muted buttons>>`;
  - `<<sg-alarm bg "#cc0000" color "#000000" size 70 blink 1 sound "…" volume 80 loop close click|time|master seconds 5 goto "Start">>текст<</sg-alarm>>`;
  - `<<sg-dialog "Надпись" title "Заголовок" passage "…" button close ok|time ok "Принято" seconds 5>>текст<</sg-dialog>>`;
  - `<<sg-code password var "$inputCode" button "Подтвердить" gap 4 focus clear table>>` + `<<sg-case "11111" goto … title … passage … sound …>>текст` + `<<sg-wrong title "Ошибка">>текст` + `<</sg-code>>`;
  - кнопка на экране — `<<sg-place kind amber corner tr x 5 y 2.75 hover none click "Нажатие">><<link "РАД">>…<</link>><</sg-place>>`;
  - таймер — `<<sg-timer "Clocks" hours 0 minutes 0 seconds 5 goto "Start">>` (`title`/`text`/`passage`, `sound`, `start running`, `hidden`, `font`, `color`, `bg`, `size`, `border`, `glow`, `format hms`);
  - цепочка видео — `<<sg-chain width 1000 height 1000 goto "Start" …>>` + `<<sg-step "media/video/a.mp4" next click|end|time seconds 2 loop muted>>` + `<</sg-chain>>`;
  - окно KR2 — тег `kr2`, `<<kr2image>>`, `<<kr2layout 50 65>>`, `<<kr2vars>>строки<</kr2vars>>`, `<<kr2main>>…<</kr2main>>`; строка с условием — `<<if $flightlog1>>Журнал полёта: найден<br><</if>>\`.
  - Внутри тревоги, окна и кнопки на экране блоки, эффекты и ссылки тоже находятся (щёлкается самый внутренний). Непонятые слова форма сохраняет.
- **Логика (обычный SugarCube; заходы и коды сотрудников — функции движка):**
  - условие — `<<if $a gt 1 and $b>>текст<<else>>другой текст<</if>>`; включена — `$a`, выключена — `not $a` (понимает и `!$a`), равна — `is`, не равна — `isnot` (понимает `!=`, `!==`, `neq`), больше — `gt`, меньше — `lt`; все условия через `and` или все через `or` (связки в кавычках и скобках не режутся). **С сессии 13:** был на экране — `setup.visits("Экран") gt 0`, не был — `is 0`, не меньше N раз — `gte N`, ровно N — `is N`; сотрудник ввёл код — `setup.entered("2", "101")`, не ввёл — `not setup.entered(…)`. Форма понимает `<<if>>` с одним `<<else>>`; с `<<elseif>>` — не открывает;
  - состояния — `<<switch $PRCD>>` / `<<case 0>><span class="red-big">Данные повреждены</span>\` / … / `<</switch>>`;
  - значение — `<span class="sg-value">Глава: <<= $chapter>> из 5</span>`; да-нет словами — `<<= $log ? "найден" : "не найден">>`; число заходов — `<span class="sg-value">Заходов: <<= setup.visits("Экран")>></span>`.
- **Ссылка ↔ кнопка (сессия 9):** `<<link …>>…<</link>>` ↔ `<<button …>>…<</button>>`; `[[Текст|Экран][$x to 1]]` → `<<button "Текст" "Экран">><<set $x to 1>><</button>>`; кнопка без своего кода → снова `[[…]]`. Вид — обёртка `<span class="…">`.
- **Действия ссылок, кнопок, горячих клавиш и кодов (`signaly-actions.ts`)** — команды внутри `<<link "Надпись" "Экран">>…<</link>>` / `<<button>>` / `<<sg-key>>` / `<<sg-entry>>`, по порядку, затем переход:
  - переменная — `<<set $x to 2>>`, `<<set $x += 1>>`, `<<set $x -= 1>>`, `<<set $x to !$x>>` (понимает `=` и `not $x`);
  - звук — `<<audio "кто" [volume 0.1] [time 999] [loop|unloop] [play|pause|stop|fadeto 0.2|fadeoverto 2 0.2]>>`; «кто»: файл, группа (`":RADIO"`), `":playing"`, `":paused"`, `":all"` с `:not(:ГРУППА)`, иначе — «другое»; плейлист — `<<playlist "имя" … skip>>`; несколько действий в одной команде, `mute`, `goto`, `load` — строкой «Код»;
  - звук-сигнал — `<<sg-sound "media/audio/x.wav" volume 100 [keep] [duck "кто" to N]>>`: отдельный `Audio` мимо SimpleAudio; без `keep` — каждый раз с начала, с `keep` — не перебивает, пока звучит; файлы загружаются заранее; в предпросмотре молчит при «Без звука»;
  - окно-сообщение — `<<sg-open "Заголовок" passage "Экран" close ok|time ok "Принято" seconds 5>>текст<</sg-open>>`; форма понимает и старый вид `<<script>>Dialog.create…<</script>>`;
  - запустить таймер — `<<sg-timer "Имя" … hidden>>`; остановить — `<<sg-timer-stop "Имя">>`;
  - «Если … то … иначе» — `<<if условие>>действия<<else>>действия<</if>>` (с `<<elseif>>` — «Код»); внутри — свои списки;
  - «Через N секунд» — `<<timed 8s>>действия<</timed>>` (понимает `500ms`; с `t8n` или `<<next>>` — «Код»). **При переходе на другой экран отсчёт отменяется** (решение 73; оставлено так — решение 75, ответ 7А);
  - «Прогресс вводящего +N» (сессия 12) — `<<sg-progress 1>>` (можно отрицательное); в списке действий — только в окне «Коды» (`ActionList codes`); вне кода ничего не делает;
  - «Вернуться на экран, где были» (сессия 13) — `<<sg-back>>`; в списке — везде;
  - «Музыка» (сессия 26) — `<<sg-mus …>>`;
  - всё прочее — строка «Код»;
  - разметка `[[Надпись|Экран][$x to 1]]` остаётся разметкой, пока действий не больше одного и это изменение переменной; иначе — `<<link "Надпись" "Экран">>`. Нетронутое действие и ссылка записываются дословно (`raw`);
  - вид ссылки — обёртка `<span class="…">`; у кнопки на экране — слово `kind` в `<<sg-place>>`.
- **Таймеры в игре:** переменная `$sgTimers` = `{имя: {end, goto, title, text, passage, sound}}`; движок раз в 0,25 с обновляет табло и по окончании выполняет действие. Автокопия хранит таймеры отдельно (поле `timers`).
- **Эффекты текста** — обычные команды SugarCube и HTML (`<<type … after>>`, `<<timed … after>>`, `<<timed>>…<<next>>`, смена `<span id="sg-swap1">` + `<<replace>>`, `<span class="sg-blink" data-sg-start>`, `<span class="glitchy" data-text data-sg-after>`); несколько эффектов — вложенные команды.
- Автокопия — `localStorage`, ключ `СИГНАЛЫ/автокопия/<IFID>/<имя файла>`; отметки событий пишутся в неё сразу, как меняются (`saveVars`). Настройки программы: «Закрепить» — `signalyDragLock`, «Без звука» — `signalyPreviewMute`, папки игры — `gameFolders` по IFID истории.

2. **Помехи:** вкладка «История» → «Музыка» → внизу раздел «Помехи»: папка на каждый вид радио с эфиром. Старые помехи видов уже перенесены сюда — нажмите «Сохранить». Трек помехи — как обычный, плюс «Слышно в пределах ±». В окне «Радио» порядок видов (▲ Выше, ▼ Ниже) — порядок радио в игре.
3. **Радио с декодером:** «Радио» → «Добавить вид» → тип «С декодером, каркас Д2» → «Сохранить». На экран — «Добавить блок» → «Радио» → этот вид.
4. **Картинка SSTV:** положите в папку игры звук с картинкой SSTV (например, сделанный программой MMSSTV или найденный в интернете: Robot 36, Martin, Scottie, PD) и добавьте его в «Музыке» как помеху или передачу эфира → «Сохранить». В шапке окна — «Картинок SSTV: N».
5. **В игре:** «ДЕКОД» → «ПОИСК» → найти передачу или помеху с картинкой: в окне слева строка за строкой набирается картинка. Неточно настроились — с шумом. Щелчок по окну — на весь терминал. Помеху тоже можно поймать — она в каталоге, папка «Помехи».
6. **У всех радио** — «СЛУЧАЙНО» и полоса прогресса. **Лампочка** — свой цвет в окне «Радио». **«Проверить историю»** — треки без копии для реверса и кнопка «Сделать копии».
